\section{Introduction}

This project applies Playwright with Python to test AskTheMenu, a restaurant website. Four main features were selected: chat, menu browsing, the kitchen dashboard and QR table links. Each feature has three end-to-end tests: two positive cases and one negative case. The project also includes four API tests covering CRUD and two network-mocking tests.

Tools used: Python, Playwright, pytest and pytest-html. Tests were run on Chromium, Firefox and WebKit against the local website.

\section{API testing and network mocking}

The API tests use Playwright's request context to send POST, GET, PATCH and DELETE requests. Create, read and update use orders; delete uses an owned chat. The tests check the response status and returned data, and confirm that changes were saved. They also check invalid input, a missing route and a request without a session.

The two network-mocking tests use page.route() to simulate an empty chat response and an HTTP 500 server error. Each test checks that a message appears, the input remains usable and the user can send another message.

\section{Test results}

There are 18 test cases. The 12 end-to-end tests and two mocking tests run in each of the three browsers, giving 42 browser runs. The four API tests run once, giving 46 runs in total. All 46 passed.

\section{Intentional bug demonstration}

To show that a test can catch a website bug, the menu heading was deliberately changed from Restaurant Menu to Unavailable menu. TC-04 still expected Restaurant Menu, so it failed in Chromium, Firefox and WebKit. After the correct heading was restored, the same test passed in all three browsers. The script demonstrate\_bug.py repeats this demonstration.
